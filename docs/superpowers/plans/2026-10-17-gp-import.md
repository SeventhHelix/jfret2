# Guitar Pro import (section of one track)

Goal: open a Guitar Pro file (.gp3/.gp4/.gp5/.gpx/.gp), pick one instrument track and a range of bars (or a named section like "Solo"), and import just that part as the current riff, keeping rhythm, tempo, time signature and tuning wherever jFret can represent them.

## Library

`@coderline/alphatab` 1.8.4 (MPL-2.0). Only `importer.ScoreLoader.loadScoreFromBytes` is used, no rendering or audio. It is ~1.1 MB minified, so it's loaded with a dynamic `import()` the first time a file is opened; the main bundle stays the same size.

Facts checked against the real library (GP7 round trip in Node):
- 960 ticks per quarter (jFret uses 24, so divide by 40). `masterBar.start` is absolute, `beat.playbackStart` is relative to the bar.
- `note.string` counts from 1 = lowest string; `staff.tuning` is listed high to low. jFret string = `tuning.length - note.string`.
- Sections (`masterBar.section.text`), time signature and `tempoAutomations` live on master bars, shared by all tracks.
- Ties (`isTieDestination`), dead notes, grace notes, bends, slides, hammer/pull, vibrato, harmonics, palm mute are flags on notes/beats.

## Modules

### `src/import/gpScore.ts` (pure, no alphaTab)
Plain intermediate types and all decisions, so they're unit-testable without the library.

```ts
type GpBar   = { start: number; num: number; den: number; tempo: number; section?: string; repeat: boolean };  // start in jFret ticks (float)
type GpNote  = { bar: number; start: number; dur: number; string: number; fret: number; tie: boolean; fx: Fx[] };  // string 0 = track's top string
type GpTrack = { name: string; tuning: number[]; capo: number; notes: GpNote[] };                                   // tuning high -> low
type GpScore = { title: string; artist: string; bars: GpBar[]; tracks: GpTrack[] };
type Fx = 'dead' | 'grace' | 'bend' | 'slide' | 'legato' | 'vibrato' | 'harmonic' | 'mute';
```

- `sections(score)` -> `{ name, first, last }[]` from section markers (a section runs to the bar before the next marker).
- `barCounts(track, bars)` -> notes per bar, for the density strip.
- `fitTuning(tuning, capo)` -> `{ tuning: TuningId, offset, shift, exact }`:
  1. Capo is folded into the frets (fret + capo) with a note in the warnings.
  2. Try every jFret tuning and string offset (0 for 6+ strings, top-aligned; 0..6-n for fewer strings). Exact pitch match wins; next best is the same intervals moved by `shift` semitones (smallest |shift|): frets are kept so the shapes stay right, playback sounds `shift` off (e.g. Drop C -> Drop D shapes, 4-string bass -> the low 4 guitar strings, an octave up).
  3. Otherwise Standard, re-fretting every note by pitch.
- `extractSection(score, track, first, last)` -> `{ song: Song, warnings: string[], noteCount }`:
  - Notes of bars `first..last`, times shifted so bar `first` starts at 0, end clipped to the section end.
  - Ties merge into the previous note on that string *before* any re-fretting, so a moved note keeps its tie (a tie whose start is outside the section becomes a normal note).
  - Dead and grace notes are dropped (counted). Other techniques are kept as plain notes and counted.
  - Strings that don't exist after fitting (7th string, bass B string) or notes needing re-fretting: move by pitch to the nearest string with fret 0..24; drop if none.
  - Rounding to jFret ticks (start and end separately, dur >= 1); count notes whose timing moved.
  - Tempo and time signature from bar `first` (bpm clamped 30..300; unsupported time signatures fall back to 4/4). Warn when either changes inside the section, and when the section has repeat signs (imported as written).
  - Title: `Song · Section` or `Song · bars a-b`.
  - Result goes through `normalizeNotes`.

### `src/import/gpRead.ts` (alphaTab)
`readScoreFile(bytes): Promise<GpScore>`: dynamic-imports alphaTab, loads the score, converts it into the plain types (every voice of the track's first staff, rests skipped, effective tempo carried forward bar to bar). Percussion tracks are left out.

### Store (`state/store.ts`)
- `importDialog = signal<{ file: File } | null>(null)`, `openImport(file)`.
- `importSong(song)`: like `newSong` without the confirm: one undo step, resets cursor/selection/loop/playhead/feel.

### UI
- **Entry points:** an `Import…` button in the edit row next to `New riff` (hidden file input), and dropping a file anywhere on the page.
- **`ui/ImportDialog.tsx`** (modal, Escape/Cancel closes):
  - Header: song title and artist. While loading: "Reading file…"; on failure: "Couldn't read this file" with the error.
  - **Track** list: name, string count + fitted tuning, note count. Defaults to the first track with notes.
  - **Sections:** clickable chips `Solo · 41–56` that select that range.
  - **Bar strip:** one small cell per bar, shaded by the selected track's note density (so you can see where the busy part is), section starts marked. Click picks a bar, shift-click or drag extends the range. Plus `Bars [a] to [b]` number inputs.
  - Summary: `16 bars · 212 notes · 4/4 · 132 bpm · Standard`, then the warnings.
  - `Import` (disabled when the range has no notes) replaces the current riff; the button title says Undo brings the old one back.
- Time signature `<select>` in the transport gains the current signature as an option when it isn't one of 4/4, 3/4, 6/8 (imports can bring 5/4, 7/8, 12/8...).

## Tests
- `gpScore.test.ts` (pure): section ranges; bar counts; fitTuning for Standard, Half step down, Drop C (-> Drop D, shift -2), 4-string bass (offset 2, shift -12), 7-string (top 6 = Standard), odd tuning (fallback, re-fret by pitch), capo; extractSection for offset/clipping, ties, dead/grace dropping, rounding counts, tempo/time signature + change warnings, re-fretting, title.
- `gpRead.test.ts`: build a score in alphaTex, export it with alphaTab's `Gp7Exporter`, read the bytes back through `readScoreFile`, check tracks, tunings, sections, tempos, string mapping, triplet timing, ties.
- Browser: open the dialog with a generated .gp file, switch tracks, pick a section, import, play.

## Out of scope
Plain-text tab paste, links/search, keeping techniques (bends etc.) as data, expanding repeats, multi-track import.
